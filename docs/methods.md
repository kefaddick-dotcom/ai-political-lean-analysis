# Methods: linguistic coding framework and analysis plan

**Goal:** build a query bank that reproduces the distribution of linguistic features real people use when they ask chatbots about politics.

1. Code every participant query for linguistic features
2. Find query types statistically
3. Generate controlled variants of each type

**Unit of analysis:** the speech act (one query can contain several).

---

## 1. Features coded

### Automatic (see [`scripts/python/auto_features.py`](../scripts/python/auto_features.py))

| Feature | Method |
|---|---|
| Length | words and clauses per speech act |
| Clause type | auto-suggested, checked by a coder |
| Wh-word | auto |
| Modals | auto |
| Negation | auto |
| Person (1st, 2nd, 3rd) | auto |
| Hedges and epistemic markers | auto (published hedge lexicon) |
| Orthography | auto (case, punctuation, textspeak) |
| Turn position | parsed from the Query ID |

### Human-coded (see [`codebook/`](../codebook/))

| Domain | Codes | Framework |
|---|---|---|
| Speech act | Primary act (summary, explanation, evaluation of fairness, opinion, prediction, personal advice, verification, clarification, pushback, meta); directness | Searle (1976) |
| Presupposition | Y/N; trigger type (factive verb, evaluative description, change of state, "why" question); direction; leading construction (tag question, negative polar) | Levinson (1983) |
| Stance | Evaluative language (presence, polarity, target); partisan coded terms; stance disclosure | Appraisal theory, Martin & White (2005) |
| Sequence | Relation to previous model turn (new, continuation, uptake) | |

## 2. Reliability

- Pilot coding on 50 queries, then codebook revision
- Double coding plus consensus meetings (see [`templates/`](../templates/))
- Coders are blind to participant demographics, including political stance
- Codebook frozen on OSF before main coding
- Krippendorff's alpha ([`scripts/python/reliability.py`](../scripts/python/reliability.py)): alpha >= .80 for speech act, >= .70 for everything else

## 3. Finding query types

**Latent class analysis** ([`scripts/R/02_query_types_lca.R`](../scripts/R/02_query_types_lca.R))
- Sorts queries into types that aren't defined in advance, e.g. "casual indirect fairness question with an evaluative presupposition"
- Outputs class sizes (sets each type's share of the query bank), feature profiles, and each query's membership probabilities
- 5 to 8 indicator codes; near-duplicate codes merged
- Pre-registered selection rule: lowest BIC, unless a class is < 5% or indistinguishable, then the next-lowest

**Embedding clustering** (robustness check)
- Sentence-BERT embeddings, clustered within each speech act
- HDBSCAN by default; k-means + silhouette (k = 2 to 10) as a check
- If LCA classes and embedding clusters roughly agree, the types are robust

**Study 1 descriptives** ([`scripts/R/01_study1_descriptives.R`](../scripts/R/01_study1_descriptives.R))
- Speech act frequencies with cluster-bootstrap 95% CIs (resample participants, not turns)
- Speech act transition matrix (does the conversation start neutral and escalate?)
- Multinomial mixed model: `speech_act ~ turn_position + (1 | participant)` in brms

## 4. Building prompt variants

**Rule:** keep propositional content and speech act fixed; vary surface form in controlled ways.

- **Natural variants:** real queries from the same class
- **Minimal pairs:** change exactly one coded feature and nothing else
- **Register-shifted variants:** the prototype rewritten in instrument register, so everyday and instrument prompts match on content

**Quality checks**
- Two coders independently judge each pair: "Are these asking the same question?"
- Embedding cosine similarity to the prototype must stay above a pre-registered threshold
- Variants are never generated by an LLM (that would defeat the point of studying natural wording)

**Which words might move the response**
1. Theory-driven candidates (presupposition triggers, evaluative and partisan terms, leading constructions, requests for the model's own opinion)
2. Corpus-driven: keyness of left- vs. right-leaning participants' queries, log-odds ratio with informative Dirichlet prior (Monroe et al., 2008)
3. Response-driven confirmation in Study 2's minimal-pair subset

## 5. Study 2 analysis plan

([`scripts/R/03_study2_models.R`](../scripts/R/03_study2_models.R))

| RQ | Question | Outcome | Model |
|---|---|---|---|
| 2.1 Direction | Is the average lean different from neutral? | Sign of non-neutral responses | Mixed logistic regression, intercept vs. 0 |
| 2.2 Register | Does register change the size of the lean? | \|lean\| = 0, 1, 2 | Ordinal mixed model (clmm) |
| Features | Which words/structures push lean left or right? | Signed lean -2 to +2 | Ordinal mixed model, minimal-pair subset |
| 2.3 Stability | Same prompt, same answer? | Repeated runs | Flip rate, entropy, ICC |

Full feature model:

```r
clmm(lean ~ register * llm
     + presupposition + evaluative + clause_type + stance_disclosure
     + (1 | case) + (1 | prototype/variant), data = responses)
```

- `register x llm`: the register effect, and whether it differs by chatbot
- `llm` uses sum coding: each chatbot vs. the grand average
- `(1 | case)`: results generalize beyond the six political issues
- `(1 | prototype/variant)`: 50 runs of one prompt aren't 50 independent data points
- Apolitical controls analysed separately; they should show near-zero lean

**Why ordinal:** lean is ordered but the gaps between points aren't necessarily equal. A linear model can distort effect sizes and create false positives, especially with responses bunched at 0 (Liddell & Kruschke, 2018). Results read as odds, e.g. "presupposition increases the odds of a more right-leaning response by 1.8x."
